# AI 漫剧小说工作流 Skill

这是一个面向 Codex 的中文 AI 漫剧小说创作 Skill。它把素材分析、原创选题、故事设定、大纲强化、分集正文、内容风险检查和人物/场景确认提示词组织成一套可重复执行的工作流。

## 主要能力

- 从用户提供的小说、故事、笔记或大纲中深度拆解 5-8 个受众与爽点机制，并把原素材证据、可迁移机制和必须替换的外壳分开记录
- 提供 5-8 个原创选题，并等待用户选择后继续
- 建立故事圣经、核心大纲和强化大纲
- 由用户确认大概目标集数、第一集时长和成片形态，不设置固定总字数
- 按纯解说旁白、对话剧情或复合型估算小说正文容量，正文仍保持正常小说格式
- 锁定叙事人称与视角人物，并阻断正文和发布说明中的视角漂移
- 为每集设计独立的开头留存钩子、观众价值点和爽点节奏
- 按 2-3 集一批自动推进，并维护进度、伏笔、关系和累计字数
- 检查正文中的意外英文、分集字段缺失和爽点节奏问题
- 输出主要人物和关键场景的 16:9 视觉确认提示词
- 最终导出干净的 Word 阅读稿，移除创作过程标注

## 创作原则

本 Skill 只提取素材中的题材需求、情绪机制和叙事结构，不复制原素材具有辨识度的角色、情节顺序、段落或对白。

开头钩子、本集价值点、明确爽点和集尾钩子是四个不同任务：

- 开头钩子负责让观众进入本集
- 本集价值点保证观众看完有所获得
- 明确爽点负责阶段性的情绪释放
- 集尾钩子负责推动观看下一集

第一集执行最强开头标准，前 3 集维持高留存，后续集数轮换钩子类型，避免连续使用同一种刺激。

## 使用示例

上传或粘贴参考素材，然后发送：

```text
使用 ai-comic-novel-workflow 分析这些素材，先给我原创选题，不要直接写正文。
```

Skill 会先展示完整选题列表。选定题目后，它会先询问大概目标集数、第一集目标时长和成片形态，再生成故事设定与大纲。第一集可在 1-5 分钟内选择，第 2 集起根据剧情密度在 1-2 分钟内弹性设计。纯解说旁白按每分钟 330-500 个小说正文字符估算，对话剧情按 360-440，复合型按 350-450；这只是正文容量估算，不把小说拆成画面、旁白、对话或音效轨。目标集数默认允许上下浮动 10%，且至少允许增减 1 集；例如目标 50 集时，最终应在 45-55 集内，不能只写到 40 集。若剧情确需超出区间，必须先说明原因并取得用户确认。

也可以直接说明创作条件：

```text
根据这些素材创作一部 24 集的都市悬疑漫剧小说。第一集 3 分钟，后面根据剧情在 1-2 分钟内安排；成片采用复合型，小说正文保持正常小说格式；使用第一人称并固定跟随女主角，自动分批，每批 3 集。
```

## 默认工作流

1. 素材与爽点机制深度分析（5-8个机制，含双证据、观众心理、运行链、升级与原创边界）
2. 5-8 个原创选题
3. 用户确认大概目标集数、第一集时长和成片形态
4. 故事圣经
5. 核心大纲
6. 强化大纲
7. 内容风险审查
8. 用户确认创作方案
9. 分批创作正文
10. 质量、连续性和语言检查
11. 人物与关键场景确认提示词
12. 最终润色与 Word 稿导出

## 分集质量门

- 不设置固定总字数，以用户确认的大概目标集数、默认允许区间和剧情闭环作为完成标准
- 第一集目标时长由用户确认，必须在 1-5 分钟内；选择“按建议”时默认建议 3 分钟
- 第 2 集起每集目标时长按剧情在 1-2 分钟内弹性安排
- 纯解说旁白按每分钟 330-500 个小说正文字符估算；对话剧情按 360-440；复合型按 350-450
- 字数估算只约束正常小说正文容量，不加入镜头、停顿、转场或分轨格式
- 叙事人称和视角人物一经确认，每批与终稿都必须通过视角合同检查
- 每集必须有观众价值点
- 任意连续 3 集至少有一个明确爽点
- 任意连续 6 集至少有一次强兑现或阶段高潮
- 不允许连续两集只有铺垫
- 第一集开头评分至少 9/10
- 第 2-3 集开头评分至少 8/10
- 后续集数开头评分至少 7/10
- 连续 3 集不得使用同一种开头钩子
- 工作稿的创作标注放在正文之前，最终 Word 稿自动移除
- 强化大纲统一使用逐集卡片，不使用横向宽表格

## 校验工具

仓库提供四个基础校验脚本：

```text
scripts/count_chinese_characters.py
scripts/validate_source_payoff_analysis.py
scripts/validate_chinese_manuscript.py
scripts/validate_episode_payoffs.py
```

它们分别负责正文字符统计、来源爽点分析深度、意外英文检查，以及时长/开头钩子/价值点/爽点节奏检查。来源分析校验要求5-8个机制卡、每卡两条素材证据，并明确可迁移机制与必须替换外壳；正文字符统计用于制作记录和异常检查，不作为总长度门槛。

生产执行还提供六个闭环工具：

```text
scripts/project_state.py
scripts/estimate_novel_word_count.py
scripts/run_batch_checks.py
scripts/validate_narrative_contract.py
scripts/export_final_docx.py
scripts/verify_final_docx.py
```

它们分别负责唯一项目状态、按成片形态估算小说正文字数、批次事务校验与恢复点提交、叙事人称/视角人物合同、Word 正式稿导出、Word 内容验收。`run_batch_checks.py` 会统一调用结构、语言、正文密度、批次衰减、叙事视角和逻辑审查门，只有全部通过才更新 `project_state.json`。

长篇质量与逻辑发布还提供：

```text
scripts/validate_manuscript_quality.py
scripts/validate_logic_review.py
scripts/validate_release_consistency.py
references/logic-common-sense-review.md
```

批次现在同时检查与成片形态匹配的正文每分钟密度、滚动批次衰减、叙事视角合同和九维逻辑/常识证据。每个逻辑维度必须记录一次具体反证挑战及结果，避免用“已检查”冒充审查。未解决的高风险逻辑问题会阻断恢复点提交；改变核心设定、主线、主要人物命运或结局的修复必须先记录用户确认。终稿只有在世界规则、人物弧、反派因果链和伏笔均有正文证据时才能导出。

## 目录说明

- `SKILL.md`：Skill 的轻量入口和核心执行要求
- `agents/interface.yaml`：Codex 显示与运行兼容信息
- `references/`：完整工作流、开头钩子、爽点、内容边界和交付格式
- `scripts/`：确定性校验工具
- `reports/`：Skill 工程与输出风险分析资料

## 不适用范围

本 Skill 不用于：

- 模仿或复刻某部受版权保护作品
- 单段文字的简单润色
- 直接生成图片或视频
- 保证作品一定通过某个平台审核

平台规则会变化，最终发布前仍应根据目标平台的最新要求进行人工检查。
